# 博主蒸馏助手

研究一个博主持续产出的机制，再把有用的结构转成用户自己的内容方法。输入是用户提供的公开内容、导出表或链接；本 Skill 不负责抓取数据，也不把互动量当作销量证明。

## 输入与预检

- 接收表格、CSV、TXT、Markdown 或用户提供的可访问链接。确认标题、正文、发布形式、时间、点赞／收藏／评论等可用字段，不依赖固定列序。缺失的指标留空，不编造。
- 记录样本数量、来源、时间范围和收集方式。若只有少数样本，说明分析只能形成线索；若混有广告或转载，单独标记。
- 先问清用户希望借鉴的是什么：选题、结构、产品衔接，还是账号定位。没有必要默认生成整套新 Skill 或 100 个选题。

## 分析流程

1. **选题矩阵**：阅读标题和正文，将作品按读者问题、场景和内容任务分类。每类列出代表作品、频次、互动分布、常用标题结构。分类来自样本本身，不强制固定栏目数；无法归类的内容单独解释。
2. **内容方法**：从代表作品抽取问题切入、证据组织、叙述节奏、示例方式、产品提及方式。每个结论至少能回指一组样本；区分稳定做法和偶然高表现。
3. **表现差异**：比较高互动与普通作品，以及图文、视频或不同时段的差异。平台分发、粉丝基础和发布时间可能影响结果，不把相关性写成因果。
4. **可迁移模型**：为实际反复出现的模式写出适用场景、输入、步骤、注意事项、一个源作品索引和一个用户可做的变体。若证据足够，可整理五个左右不同模型；不凑数量。
5. **差异化**：让用户提供自己的经历、读者、产品和不愿模仿的部分。指出哪些只是通用结构，哪些是该博主的独特表达、故事或视觉资产，不建议照搬后者。

## 交付

默认给一份 Markdown 分析报告：样本说明、选题矩阵、内容方法、表现差异、可迁移模型、用户自己的差异化方向、证据缺口。关键判断附来源作品标题或用户数据中的行号。

用户提出时，再追加以下产物：

- **选题库**：按矩阵生成与用户自身场景相符的标题／主题，并标注所回应的用户问题。要 100 条时，只在材料足以支撑独立角度的情况下生成；不足时给可用数量和缺口，不靠同义改写凑数。
- **交互校准**：用用户的一个模糊想法提出三个不同方向和提纲，说明如何借用了结构、又在哪里加入用户自己的证据。经用户反馈再调整。
- **衍生创作 Skill**：仅当用户明确要求时，生成针对其自己账号的 Skill 草稿，写明目标读者、选题原则、论证结构、证据要求和避免复制源博主的规则。保存到用户指定的位置，不默认安装或发布。

输出位置默认为当前对话或用户指定的本地文件。写入飞书、Notion、GitHub 或其他外部应用须按用户当次要求和可用权限执行；不能把这些平台当作运行前提。

## 边界

- 研究的是可迁移的选题和论证机制，不复制原帖正文、完整标题库、私人素材或视觉资产；示例引用保持必要且简短。
- 不以“连续若干字不同”作为唯一原创标准；比较核心表达、结构组合和读者得到的实际增量。
- 博主表现只能提示内容可能吸引关注，不能证明用户做同类产品会成交。
- 不要求特定操作系统、电脑目录、飞书 CLI 或某个 Agent 产品。表格工具不可用时说明限制，仍处理可读取的数据。
