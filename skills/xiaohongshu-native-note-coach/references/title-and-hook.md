# Title And Hook

## Title Output

Generate 5 titles by default:

1. 痛点型
2. 判断型
3. 方法型
4. 场景型
5. 反差型

Prefer 20 Chinese characters or fewer when possible. No emoji by default.

## Title Patterns

- 你不是 X，是 Y
- X 之后，我终于明白了 Y
- 普通人想 X，先做 Y
- AI 时代，最该练的是 X
- 真正厉害的 X，都有一个 Y
- 别再 X 了，问题在 Y
- 我用 X，跑通了 Y
- 从 X 到 Y，我只做对了这件事
- 为什么你越 X，越 Y
- 这张图让我意识到 X

## User Positioning Title Angles

Prefer angles around:
- AI 聊完就忘
- 知识和灵感散落
- 目标定了就散
- 私有上下文
- 从用户已经发布的内容、真实产品和读者反馈里提取主题；不要预置某个创作者的产品主题。

## Opening Rules

The first sentence must be direct and scene-based.

Good openings:
- `最近做成了一件小事，但它让我确认了一件事。`
- `这张图背后，其实是我最近最重要的一次系统升级。`
- `我越来越觉得，AI 时代最贵的不是工具，而是判断。`
- `以前我也以为，记录只是记录。后来发现，记录其实是在训练另一个自己。`

Avoid:
- slow WeChat-style openings
- generic platform greetings
- "今天想和大家分享..."
- abstract concept first without scene
- result claim without context

## CTA Patterns

Use the lightest CTA that matches trust role:

- Comment cue: `你现在最卡的是哪一步？`
- Private chat cue: `如果你也在处理这个问题，可以说说你卡在哪一步。`
- Keyword cue: `想看这套流程，可以评论关键词：系统。`
- Product cue: 只有用户提供并确认真实产品与适用边界时，才用该产品的准确名称和实际解决的问题表述。
- No CTA: use for purely personal/story notes.

Use a product name only when the user has supplied or confirmed it as the public name. Otherwise use verified category wording. Titles must not expose internal project/template names or promise results that the images and sources cannot support.
