# Case-Derived Logic for One-Person Virtual Product Selection

## Core Case Patterns

### Sell Scenes, Not Categories

Do not recommend broad products:

- "English materials"
- "PPT templates"
- "AI prompts"
- "career course"
- "education resources"

Convert them into paid scenes:

- "真实职场英语听力库"
- "职场新人自我介绍 PPT"
- "小学班主任开学第一个月控班资料包"
- "用户运营面试救急包"
- "外企会议表达工具箱"

The narrower the scene, the clearer the buyer's reason to pay.

### Cut Big Markets Into Small Buyer Tasks

Use this formula:

`big market -> specific buyer -> immediate task -> concrete result`

Examples:

- English -> foreign-company newcomer -> English meeting tomorrow -> sound more professional
- Education -> new head teacher -> first month class control -> stable class order
- Career -> JD procurement candidate -> interview prep -> fast question familiarity
- Renovation -> first-time renovator -> budget and material decisions -> avoid costly mistakes

### Every Industry Can Have a Library

Transfer this pattern aggressively:

- Every role can have a material library
- Every role can have a question bank
- Every industry can have a beginner guide
- Every recurring task can have templates
- Every complex decision can have a checklist
- Every scattered field can have a knowledge base

Ask:

- What do beginners always ask?
- What do experienced people repeatedly reuse?
- What documents, scripts, templates, cases, or hidden rules exist?
- What is annoying to search, judge, or organize?

### Productize Personal Experience

Personal experience becomes sellable when structured as:

- steps
- checklists
- pitfalls
- examples
- templates
- decision rules
- scripts
- workflows
- before/after comparisons

Do not call it "my experience". Package it as a result-oriented artifact:

- "第一次装修小白预算避坑清单"
- "10万字跨境电商一人DIY手册"
- "新手班主任实操指南"
- "线上脱单初期聊天话题库"

### Curate and Re-Structure, Don't Merely Move Files

For resource packs, value comes from:

1. selecting
2. classifying
3. ordering
4. explaining
5. turning into a use path

Simple bundles are low-value and may carry copyright risk. Structured interpretation is stronger:

- external articles -> writing training system
- public reports -> industry insight pack with categorization and commentary
- YouTube/Reddit resources -> curated learning path
- scattered renovation content -> searchable knowledge base

### AI Must Attach to an Existing Scene

Do not recommend "AI prompt pack" alone. Use:

- AI + teacher comments
- AI + lesson preparation
- AI + interview assistant
- AI + meeting expression
- AI + naming
- AI + worksheet/question generation
- AI + report/diagnostic generation
- AI + language learning workflow

Ask:

- What repetitive task does the buyer already have?
- Can AI reduce production cost or user effort?
- Can the output be checked, edited, and used immediately?

### Users Pay for Saved Effort and Certainty

Each product should answer:

- What does it save? Time, search, judgment, trial-and-error, anxiety, communication?
- What does the user get faster?
- What mistake does it help avoid?
- What result can the user see or use immediately?

Detail-page positioning should say what the user no longer needs to do.

### Packaging Raises Perceived Value

Prefer:

- "内行人万字避坑笔记"
- "2个月啃完上百份资料"
- "真实职场场景，学了就能用"
- "面试救急包"
- "一篇文档 + 三个步骤"
- "资料 + 模板 + 案例 + 使用说明"

Avoid only listing file counts. Explain the transformation and outcome.

### Customer-Lead Products

Low-priced diagnostics, reports, checklists, and tests can work as lead products if they naturally connect to a backend:

- face/style diagnostic -> makeover or image course
- naming report -> custom naming service
- job list -> career consulting
- map listing -> local marketing service
- school choice tool -> application consulting

Guardrail: the front-end product must have real standalone value and the backend must be a natural next step.

### Heavy Delivery Warnings

Flag and reshape:

- 1v1 consulting
- long-term community management
- custom service
- psychological/medical/legal/financial advice
- strong copyright dependence
- apps/web tools requiring ongoing maintenance

Reshape into:

- PDF guide
- checklist
- template
- entry diagnostic
- knowledge base
- pre-recorded walkthrough
- AI workflow

### MVP Plan

Use this 7-day plan:

1. Day 1: define buyer and paid scene
2. Day 2: list 20 pains/questions/tasks
3. Day 3: choose deliverable and outline
4. Day 4: build core asset
5. Day 5: write title and detail-page pitch
6. Day 6: publish 3-5 content tests
7. Day 7: collect purchase signals/pre-sell

### Detail Page Skeleton

Use:

1. For whom
2. In what urgent scene
3. Why current solutions are messy or slow
4. What has been selected/structured
5. What the buyer receives
6. What the buyer no longer needs to do
7. How to use it
8. Who should not buy

### Final Recommendation Sentence

End with:

`这个人最应该先从【具体人群】的【具体场景】切入，做一个【轻交付产品形式】，因为它最符合他的经验资产，同时能低成本验证真实付费。`
