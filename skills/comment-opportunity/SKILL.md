# 评论区商机挖掘

评论能提供用户情境、语言和未解决问题的线索。互动量说明某句话引发反应，**不能单独证明付费意愿、市场规模或产品可行性**。所有产品建议都须标为待验证假设，直到有访谈、搜索、竞品交易或购买行为等独立证据。

## 输入

接收用户合法取得的 TXT、CSV、Excel、表格或粘贴文本。至少需要评论正文；点赞数、回复关系、时间、原帖主题和来源若有则一并保留。若用户提供评论者身份或私信，报告中只保留分析必需的信息，不公开个人标识。缺少原帖语境会改变判断时，先询问或明确标注限制。

先确认任务类型：A 商机研究、B 选题衍生、C 已选产品形式的主题反推。用户可以只要其中一种。C 需要知道目标用户、产品形式和交付约束；已有商机报告可作为输入，但关键原始评论仍应可追溯。

## 共用分析

1. 读取全部可用数据，统计评论数、点赞分布、回复和重复内容；清理广告、机器内容、重复转发，并说明处理方式。
2. 依据评论内容而非只按点赞，标注**问题、场景、现有做法、情绪、求助、反对意见、购买／价格线索**。点赞高的评论优先阅读，但低赞的具体失败案例也可能重要。
3. 为主题建立证据表：匿名评论编号、必要的短摘录、点赞或出现次数、它能支持的判断、不能支持的判断。不要从一条高赞评论推出“大家愿意付费”。
4. 检查偏差：原帖话题、发布者受众、平台推荐、评论样本与沉默用户都可能影响结论。没有足够证据时写“未知”。

## A：商机研究报告

输出：研究范围；问题与场景分组；已有替代方案；明确的付费或购买信号（若有）；候选产品方向；反证与待补证据；下一次访谈或小规模验证动作。每个候选方向写清谁在什么场景遇到什么阻碍、可能交付什么、主要制作与服务负担、对应评论证据，以及还缺哪一种市场证据。竞品信息只在数据中实际出现或用户另给资料时讨论。

不要把评论原话直接搬进商品、课程或广告。用户表达可作为内部研究线索；对外案例须处理身份信息，并确认有适当的使用权或改用自己的概括。

## B：选题衍生

按问题分组给出选题矩阵：目标读者、具体场景、可回答的问题、观点型或方法型切口、可提供的真实证据、相关产品（如存在）。选题标题保持自然、有立场；引用来源放在内部证据对照表，不把陌生人的原话批量改写成自己的经历。

用户要求 100 条时，先估计独立问题和角度是否足够。足够则分批生成并去重；不足则给出有证据的数量和需补充的评论类型。不能为凑数反复换词，也不能声称每条已经“市场验证”。

## C：产品主题反推

用户已指定产品形式时，逐个问：评论中的问题是否能由该产品真实解决？若能，列出主题、对应场景、必要的步骤／示例、评论证据和仍需验证的部分。若评论者与最终购买者不是同一人，明确区分两者。纯情绪或超出产品能力的问题不硬塞进目录。

## 交付与协作

默认在对话中给可复制的 Markdown 报告；用户指定时保存到本地文件或其商业系统的研究／产品／内容页。外部飞书、Notion 写入必须以当次请求、可用连接和目标核对为前提。用户只有一份评论数据时也能完成核心分析；抓取器、产品选品 Skill 或课件生产工具都不是必装依赖。

本 Skill 负责从评论提取问题和机会线索。个人条件选品交给 `$one-person-product-selection`，具体机会判定交给 `$product-opportunity-coach`，内容成稿交给对应平台创作 Skill。
